## Overview

This project provides comprehensive model explainability analysis for a Deep Q-Network (DDQN) trained to control traffic signals. It features two complementary explanation methods:

- **LIME Explainer** (`lime_explainer.py`) - Uses Local Interpretable Model-agnostic Explanations for local interpretability
- **SHAP Explainer** (`shap_explainer.py`) - Uses SHAP (SHapley Additive exPlanations) for feature importance and global interpretability

Both methods help understand which detector features influence the traffic signal switching decisions.

## Key Components

### Scripts

**LIME Explainer** (`Code/lime_explainer.py`)
- Trains a LIME TabularExplainer on background states
- Explains individual test samples' switch/stay decisions
- Generates visualizations for global feature importance, detector heatmaps, and decision dominance
- Produces comprehensive visualizations with feature weights colored by influence direction

**SHAP Explainer** (`Code/shap_explainer.py`)
- Uses KernelExplainer for global feature attribution
- Identifies which features most influence P(switch|state)
- Includes multiple visualization types for comprehensive analysis
- Implements 10+ bug fixes for stability and accuracy

### Output Directories

## Key Features & Fixes

### SHAP Explainer Improvements

The SHAP version includes these critical fixes:

1. **SAFE PARSING**: Robust checkpoint variable extraction with `_safe_sort_key()`
2. **OPTIMIZER FILTERING**: Excludes optimizer/Adam weights from loading
3. **DYNAMIC PHASES**: Live SUMO query for accurate phase count
4. **GLOBAL STATE**: `matplotlib.rcdefaults()` at module level
5. **EXPLAINER REUSE**: Single explainer instance for consistent results
6. **AUTO INTERACTION**: `interaction_index='auto'` for dependency plots
7. **DIRECT CALLS**: Eliminates `generate_and_collect()` wrapper
8. **PATH VERIFICATION**: Checks `variables/variables.index` instead of `saved_model.pb`
9. **SOFTMAX DIAGNOSIS**: Logs mean probabilities to detect saturation
10. **TRAFFIC SAFETY**: Handles vehicle cleanup during rollouts

## Technical Details

### State Vector (37 dimensions)

6 detectors × 5 features:
- Queue (vehicles)
- Occupancy (%)
- Speed (km/h)
- Mean waiting time (s)
- Emergency vehicle count

+
1. Time since last switch (normalized)
2. Phase one-hot encoding (dynamic length)
3. Pressure (normalized total queue)
4. Demand (normalized vehicle count)

### Decision Logic

The DDQN policy outputs Q-values for two actions:
- Action 0: Stay in current phase
- Action 1: Switch to next phase

Green time minimum: 25 simulation steps to prevent frequent switching.
